# 纠正与进化

## 触发

用户说出以下任意表达：
- "这不对" / "我不会这样说" / "我应该是……"
- "这不像我" / "这不是我的语气"
- "追加" / "我有新文件"

## 处理流程

### 1 判断归属

| 用户纠正的内容 | 归属 | 写入位置 |
|---|---|---|
| 事实、经历、关系、时间线 | Self Memory | `self.md` 的 `## Correction 记录` |
| 性格、态度、说话方式、禁忌句式 | Persona | `persona.md` 的 `## Correction 记录` |
| 两者都有 | 分别写入 | 两处都写 |

### 2 追加记录（保留用户原话，别改写成书面语）

```markdown
### YYYY-MM-DD（本人裁定）

| 场景 | 原表现 | 判定 | 修正 |
|---|---|---|---|
| {场景} | {原来怎么写的} | 不像 / 部分不像 | {改成什么} |

**本人原话**："{用户说的原文}"
```

### 3 同步修改正文

不要只在 Correction 里记一笔——**必须回到对应的 Layer / 章节把正文改掉**，否则下次生成还会犯同样的错。

### 4 重新合成

```bash
python tools/version_manager.py --action backup --slug "<slug>" --base-dir "<技能目录>"
python tools/build_skill.py --slug "<slug>" --base-dir "<技能目录>" \
  --self <技能目录>/<slug>/self.md --persona <技能目录>/<slug>/persona.md \
  --meta <技能目录>/<slug>/meta.json
```

### 5 反问确认

改完把新的说法再演一遍给用户看，让他判定"像 / 不像"。

## 纠正原则

1. **用户永远优先于数据。** 数据分析说他会这么说，本人说"我不会"，那就是数据分析错了，当场改。
2. **一次纠正一条。** 不要把多个纠正混在一起改，否则分不清哪条有效。
3. **删掉错的比补上对的更重要。** 错误特征会持续污染后续所有对话。
4. **留意系统性偏差**：如果同类纠正反复出现（例如连续三次"太冲了""太爱表现了"），说明初始分析里有一套先入为主的框架，要回头改分析口径，而不只是改单句。
